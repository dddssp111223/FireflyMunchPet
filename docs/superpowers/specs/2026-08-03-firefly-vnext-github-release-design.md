# Firefly MunchPet 最终版 GitHub 发布设计

日期：2026-08-03

## 目标

把本地已经验收通过的流萤桌宠最终版同步到
`dddssp111223/FireflyMunchPet`，更新公开说明，并创建新的 GitHub Release。
保留现有 Release，不覆盖历史资产。

## 发布内容

- 从隔离分支 `codex/firefly-vnext-release` 基于远端最新 `master` 整理。
- 同步流萤最终版运行源码、Godot 场景、普通/和谐素材组、提醒模块、
  自动化测试、构建与打包脚本。
- 更新 README，准确说明：
  - Windows 10/11 x64 与免安装 ZIP；
  - 回收站投喂、固定星星眼、吞咽动画、底部锚定 Q 弹；
  - 独立虹膜鼠标跟随和待机动画；
  - 普通/和谐版切换；
  - 30/50/75/100/125/150% 六档缩放；
  - 最多五项、单项 200 字的持久化提醒备忘录；
  - 独立提醒编辑窗、透明提醒气泡及本地数据位置；
  - 源码验证、构建和打包命令。
- 创建新版本标签和 GitHub Release，上传最终免安装 ZIP及 SHA-256。

## 明确排除

- 五角色桌宠工程及其成品、图片素材和生成候选图。
- `analysis/` 视觉捕获、工具缓存、Godot/.NET 本地运行时、临时导出目录。
- 工作流草稿、未纳入最终产品的脸颊拉伸交互及过期素材。

## 集成方式

1. 从远端最新 `master` 创建隔离分支。
2. 从已验收的流萤实现工作区复制明确的产品文件，不复制其 `.git` 或工具目录。
3. 对公开仓库做文件清单审计和敏感信息扫描。
4. 运行 Python 资产测试、.NET 测试、Godot 真实渲染验证、提醒窗口探针、
   Windows 回收站临时文件集成测试和 ZIP CRC/SHA-256 校验。
5. 提交发布更新，推送分支并合并到 `master`；若远端在此期间变化，先正常同步，
   不使用强制推送。
6. 创建新 Release，上传验证过的免安装 ZIP。

## 验收标准

- Git 中只出现流萤最终版和公开文档需要的变更。
- README 与托盘菜单、提醒默认值、缩放选项及实际数据路径一致。
- 所有自动测试和 Windows 集成门槛通过。
- 发布 ZIP 可通过 CRC，包含启动器、Godot/.NET 运行时、普通/和谐素材和编译程序集。
- GitHub `master`、版本标签、Release 说明和下载资产相互一致。

## 回滚

不改写历史、不强制推送。若发布后发现问题，可删除新 Release 资产并通过普通
revert 提交回滚；旧 Release 始终保留。

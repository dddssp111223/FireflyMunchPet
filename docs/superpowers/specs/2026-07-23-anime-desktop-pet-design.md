# 二次元文件吞噬桌宠：设计规格

日期：2026-07-23  
状态：已逐节确认，等待用户审阅书面规格

## 1. 项目概述

本项目把现有的单张二次元角色图片制作成一个 Windows 桌宠。用户可将文件、文件夹或多个项目拖到桌宠任意可见区域；角色会先表现出渴望，再用大口吞咽动画把项目“吃掉”。成功吞咽代表 Windows 已将项目移入回收站。

桌宠还提供待机动画、双眼鼠标跟随、全区域单击 Q 弹、画面右侧脸颊拉伸、任意位置移动、托盘控制、置顶、静音与四档缩放。

首版只支持 Windows 10/11，以免安装 ZIP 形式交付。

## 2. 目标

- 从当前单张合成图片出发完成动画素材，不要求用户自行绘制分层或动画帧。
- 最大限度保留原画风格、角色构图和浅蓝色桌面/桌沿，只移除人物周围的纯白背景。
- 让文件删除的视觉结果与真实 Windows Shell 操作保持一致。
- 正常删除不显示任何文字、成功通知或额外确认。
- 只有项目无法进入回收站而将永久删除时，显示 Windows 系统警告。
- 动画与鼠标交互流畅，同时避免透明窗口遮挡桌面上的非角色区域。
- 形成可验证、可复用的制作流程，为后续同类型角色桌宠打基础。

## 3. 非目标

首版不包含：

- macOS、Linux、移动端或 Web 支持。
- 开机启动、自动更新、在线功能、账号系统或设置窗口。
- 完整 Live2D 模型、全身骨骼运动、语音对话或复杂 AI 角色行为。
- 回收站恢复按钮；用户仍通过 Windows 回收站恢复文件。
- 角色换装、皮肤商店或运行时切换其他角色。

## 4. 已有素材与用户需要准备的内容

### 4.1 已有素材

- 原图：`01978-3283962926.png`
- 当前尺寸：512×512 像素
- 构图：角色从浅蓝桌面/桌沿后探头，适合近景互动桌宠

### 4.2 用户必须确认或提供

- 允许对原图执行去白底、保守放大、图层拆分、遮挡区补画和派生表情制作。
- 在最终阶段对视觉细节、声音和交互结果进行验收。

当前开发与验收按私人本地使用处理。若要向其他用户公开分发，用户必须先确认对原图拥有覆盖该分发范围的使用权；在确认前只交付私人测试版本，不进行公开发布。补画和派生表情仍属于原图的衍生素材，不能替代原图授权。

### 4.3 可选但有帮助

- 如果存在比 512×512 更高分辨率的原图，应优先提供；没有也不阻塞开发。
- 如果用户有指定的点击、吸入或吞咽音效，可替换默认音效；没有则由项目制作短音效。
- 如果用户有指定应用名称或托盘图标，可在发布前提供；没有则从角色图派生。

用户不需要自行准备眼睛、嘴型、头发、口水或动画帧。

## 5. 技术方案

### 5.1 技术栈

- 引擎：Godot .NET 4.7.1，Windows x86_64
- 语言：C#
- Windows 集成：Win32/OLE/Windows Shell COM
- 发布：Godot .NET Windows 导出，打包为免安装 ZIP

用户现有 Steam Godot 为 4.7.1 标准版，不包含 C# 支持。该安装保持不变。本项目单独使用官方便携式 Godot .NET 4.7.1，并需要 64 位 .NET 8 SDK 进行编译。最终导出包包含运行所需组件，目标用户不需要安装 Godot 或 .NET SDK。

参考：

- [Godot Windows 下载与 .NET 版本说明](https://godotengine.org/download/windows/)
- [Godot C#/.NET 前置条件](https://docs.godotengine.org/en/stable/tutorials/scripting/c_sharp/c_sharp_basics.html)
- [Godot 桌面窗口与托盘能力](https://docs.godotengine.org/en/latest/about/list_of_features.html)

### 5.2 主要模块

#### `PetWindow`

- 创建无边框、透明背景、非任务栏、非 Alt+Tab 的桌宠窗口。
- 维护窗口位置、四档缩放、当前显示器和 DPI。
- 根据处理后的角色轮廓设置可交互区域；其余透明像素点击穿透。
- 支持默认不置顶和用户切换置顶。

#### `PetStateController`

- 维护唯一的高层交互状态。
- 控制状态切换、动画互斥、输入优先级和恢复待机。
- 防止删除失败却播放成功吞咽。

建议状态：

- `Idle`
- `FileHover`
- `ShellPending`
- `Swallowing`
- `ClickBounce`
- `CheekDragging`
- `WindowDragging`
- `Rejecting`

#### `CharacterRig`

- 管理角色图层、骨骼、网格、表情和动画参数。
- 对外暴露语义动作，如 `SetHungry(true)`、`PlaySwallow()`、`SetEyeTarget()`。
- 不直接调用文件系统或 Windows API。

#### `NativeDropTarget`

- 在 Godot 窗口上接入 Windows OLE 拖放生命周期。
- 提供 `DragEnter`、`DragOver`、`DragLeave` 和 `Drop`。
- 只接受 Windows Shell 文件列表，不把普通文本或应用内拖拽当成删除请求。
- 让角色在文件尚未松手时即可切换星星眼。

Godot 原生 `files_dropped` 可接收落下后的路径；悬停反馈需要 Windows OLE 生命周期补充。

参考：

- [Godot Window.files_dropped](https://docs.godotengine.org/en/4.7/classes/class_window.html)
- [Windows RegisterDragDrop](https://learn.microsoft.com/en-us/windows/win32/api/ole2/nf-ole2-registerdragdrop)

#### `WindowsShellService`

- 在删除前获取并缓存项目的 Windows Shell 图标。
- 使用 `IFileOperation` 删除单个文件、文件夹或多选项目。
- 正常情况请求进入回收站且不显示确认、进度或成功提示。
- 项目无法回收而将永久删除时，显示 Windows 系统警告。
- 返回成功、用户取消或失败的明确结果。

参考：

- [IFileOperation::SetOperationFlags](https://learn.microsoft.com/fr-fr/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags)

#### `TrayController`

- 创建 Windows 通知区域图标与右键菜单。
- 提供置顶、缩放、静音、回到右下角和退出。

#### `AudioController`

- 播放点击“啵”、图标吸入“嗖”、吞咽“咕噜”和失败“咬不动”等短音效。
- 接收全局静音设置。

#### `SettingsStore`

- 在 Godot `user://` 对应的 Windows 用户数据目录保存轻量 JSON 配置。
- 保存位置、缩放、置顶与静音。
- 不写注册表。

## 6. 窗口与托盘行为

### 6.1 桌宠窗口

- 默认位于主屏幕右下角。
- 用户可拖到桌面任意位置，不限制在屏幕边缘。
- 拖动后记住位置。
- 默认不置顶；置顶后位于普通应用窗口之上。
- 不显示普通任务栏按钮，不出现在 Alt+Tab。
- 鼠标操作不抢占当前应用的键盘焦点。
- 透明区域点击穿透，不阻挡桌面图标或下层应用。

### 6.2 缩放

托盘菜单提供：

- 75%
- 100%（默认）
- 125%
- 150%

缩放时保持角色比例、交互区域和动画参数同步。位置在缩放后仍需限制在可见桌面范围。

### 6.3 托盘菜单

- `置顶显示`：可勾选，默认关闭
- `缩放`：75%、100%、125%、150%
- `静音`：可勾选，默认关闭，即默认有声音
- `回到右下角`
- 分隔线
- `退出`

显示器断开、分辨率变化或保存坐标失效时，应用自动将桌宠限制回可见工作区；`回到右下角` 提供人工恢复入口。

## 7. 素材处理与角色分层

### 7.1 基本原则

- 最大限度保留原画，不重新设计角色。
- 去除纯白背景，但保留人物、浅蓝桌面/桌沿和桌面上的口水。
- 将原图保守放大到适合 150% 显示的工作分辨率。
- 补画只限于图层移动、眨眼、嘴型切换或变形时会暴露的遮挡区域。
- 所有生成或补画结果必须经过与原图叠加对比和人工视觉检查。

### 7.2 图层结构

1. 浅蓝桌面/桌沿背景。
2. 后层头发与头饰。
3. 脸部底色。
4. 左眼眼白、虹膜/瞳孔/高光、上下眼睑。
5. 右眼眼白、虹膜/瞳孔/高光、上下眼睑。
6. 星星眼替换层。
7. 普通闭眼层。
8. `><` 吞咽闭眼层。
9. 眉毛、鼻部与腮红等表情辅助层。
10. 原始张嘴、期待嘴型、极限大口、闭嘴吞咽。
11. 舌头与口腔内部。
12. 前层刘海和左右发束。
13. 画面右侧脸颊局部变形网格。
14. 口水流。
15. 桌面口水水滩与波纹。

### 7.3 双眼跟随

- 眼白静止，只移动虹膜、瞳孔和高光。
- 左右眼分别计算目标，并受各自眼眶遮罩约束。
- 以 512×512 原图为基准，最大偏移约为横向 5–7 像素、纵向 3–5 像素，按最终工作分辨率同比例缩放。
- 目标使用平滑弹簧/阻尼跟随，不直接瞬移。
- 光标再远也只能到达限制边界。
- 虹膜始终覆盖眼眶主要区域，禁止出现整片眼白。
- 眨眼、星星眼和 `><` 表情期间暂停普通眼球跟随。

## 8. 交互命中规则

### 8.1 全区域行为

处理后的全部可见人物和桌沿区域都支持：

- 文件投喂
- 普通单击 Q 弹

文件从任何可见位置落下后，其缓存图标从落点飞向嘴部。

### 8.2 特殊拖拽区域

- 画面右侧脸颊：局部脸部拉伸。
- 头顶、头饰和上半部头发：移动整个桌宠窗口。

### 8.3 单击与拖拽区分

- 鼠标按下后，只有位移超过阈值才进入拖拽。
- 在右脸区域超过阈值：进入脸颊拉伸。
- 在头顶区域超过阈值：移动窗口。
- 未超过阈值并松开：无论位于哪个可见区域，均触发普通 Q 弹。

### 8.4 优先级

1. Windows 文件拖放
2. 超过阈值后的右脸拖拽
3. 超过阈值后的窗口拖动
4. 未发生拖动的普通单击

`Swallowing` 和 `ShellPending` 期间不接受新的投喂或鼠标互动。拖放目标向 Windows 返回暂不可接受，避免文件丢失或多次删除。

## 9. 动画设计

### 9.1 待机

- 随机间隔眨眼。
- 非机械同步的轻微呼吸和头部起伏。
- 刘海与两侧发束小幅飘动，使用不同相位和阻尼。
- 口水流缓慢左右摆动并轻微伸缩。
- 桌面口水水滩出现幅度极弱的波纹。
- 双眼在非表情状态下跟随鼠标。

待机动画应使用随机区间和不同周期，避免所有部件同时往返。

### 9.2 单击 Q 弹

- 全部可见角色区域可触发。
- 短暂整体压扁约 10%–15%。
- 随后产生一次轻微过冲拉伸。
- 使用阻尼曲线恢复原形。
- 同步播放短促“啵”音效。

### 9.3 右脸拉伸

- 仅画面右侧脸颊响应拖动。
- 使用局部高密度网格，让脸颊跟随鼠标，附近五官和发丝只受到柔和牵连。
- 设置最大拉伸距离，禁止网格撕裂或暴露空洞。
- 松手后快速弹回，并有一次小幅过冲。

### 9.4 文件悬停

- 文件进入任意可见区域即触发。
- 双眼切换为星星眼。
- 眼睛瞪大，身体/头部轻微前倾。
- 嘴巴进入期待张开状态。
- 文件拖离窗口或用户取消拖拽后，平滑恢复待机。

### 9.5 吞文件

目标总时长约 0.6–0.8 秒：

1. 缓存的实际 Windows 文件图标从落点开始快速缩小并飞向嘴部。
2. 角色瞬间张成极限大口，把图标快速吸入口中。
3. 立即闭嘴并闭眼，眼睛切换为 `><`。
4. 脸颊和头部做一次明显的向下压缩，形成下咽感。
5. 角色短促上弹，头发和口水带少量滞后晃动。
6. 恢复待机和鼠标跟随。

多项目使用叠放图标，不显示数字或任何文字。

### 9.6 删除失败

- 不播放成功吞咽。
- 角色做一次短促“咬不动”回缩或轻摇。
- 播放区别于成功吞咽的失败音效。
- 同时显示 Windows 系统错误对话框，说明占用、权限、路径等真实原因。

## 10. 文件删除数据流

### 10.1 正常回收

1. OLE `DragEnter`/`DragOver` 确认数据为文件列表。
2. 角色进入 `FileHover`。
3. 用户松手；应用立即缓存文件路径、落点和 Shell 图标。
4. `WindowsShellService` 使用 `IFileOperation` 请求回收。
5. 正常回收不显示确认、进度或成功消息。
6. Shell 返回成功后进入 `Swallowing`。
7. 动画结束后恢复 `Idle`。

### 10.2 将永久删除

1. `IFileOperation` 判断项目无法进入回收站。
2. Windows 显示系统永久删除警告。
3. 警告期间角色保持期待状态，不播放最终吞咽。
4. 用户确认且删除成功后播放吞咽。
5. 用户取消则直接恢复待机，不显示额外文字。

网络盘、U 盘、过大项目或其他无法回收的来源遵循此路径。

### 10.3 失败

1. Shell 返回权限、占用、路径不存在或其他失败。
2. 不播放吞咽。
3. 播放“咬不动”动作。
4. 显示 Windows 系统错误。
5. 返回待机。

### 10.4 安全不变量

- 只有 Shell 明确返回成功，才能播放最终吞咽。
- 取消和失败不得改变为成功动画。
- 正常成功后不显示任何文字。
- 永久删除必须由 Windows 系统警告确认。
- 快捷方式按其文件本身处理，不删除快捷方式目标。
- 所有批量项目作为同一次投喂处理，但必须检查整体操作是否被用户取消。

## 11. 设置与持久化

设置文件包含：

- 窗口逻辑位置
- 所在显示器标识或恢复所需信息
- 缩放档位
- 置顶开关
- 静音开关

启动时：

1. 读取设置。
2. 检查显示器和工作区。
3. 将无效或不可见位置限制回主屏幕右下角。
4. 应用缩放、置顶和静音。

设置损坏时使用默认值启动，不阻止桌宠运行。

## 12. 错误处理

- 素材或音效缺失：记录错误，使用安全占位或禁用对应音效，不影响退出和托盘。
- 托盘初始化失败：桌宠仍运行，但必须提供可发现的备用退出方式用于调试版本；发布前该问题必须修复。
- Windows OLE 注册失败：禁用投喂，禁止任何删除调用，并记录诊断。
- Shell 删除服务异常：不播放吞咽，显示系统/诊断错误。
- 设置写入失败：继续当前会话，不改变文件删除行为。
- 动画异常：状态机设置超时保护，确保能恢复 `Idle`，但超时不能伪造删除成功。

## 13. 测试策略

### 13.1 自动化测试

- `PetStateController` 状态转换与优先级。
- 单击和拖拽位移阈值。
- 眼球椭圆限制和最大偏移。
- 设置序列化、损坏恢复和屏幕范围限制。
- Shell 结果映射：成功、取消、失败。

### 13.2 视觉测试

- 原图和重建图层叠加对比。
- 75%、100%、125%、150% 下的边缘、表情和网格检查。
- 待机循环无明显接缝。
- 眼球极限位置没有整片眼白。
- Q 弹、拉脸和吞咽结束后准确回到基准姿势。
- 白底完全移除，桌面/桌沿和口水保留。

### 13.3 Windows 集成测试

- 单文件、单文件夹和多选项目。
- 中文路径、空格、长路径和不同扩展名。
- 快捷方式。
- 不同磁盘、网络盘和可移动盘。
- 正常进入回收站并可恢复。
- 永久删除警告与取消。
- 被占用、无权限和路径已不存在。
- 透明区域点击穿透。
- 置顶切换、缩放、静音、托盘退出。
- 重启恢复位置和设置。
- 多显示器、显示器断开、不同 DPI 和分辨率变化。

所有删除测试只使用测试代码创建的专用临时文件和目录，绝不使用用户真实文件。永久删除测试也仅针对明确创建并验证路径位于测试根目录内的临时数据。

### 13.4 发布验收

- 在干净的 Windows 10/11 环境运行免安装 ZIP。
- 目标机器不需要 Godot 编辑器或 .NET SDK。
- 无普通成功文字提示。
- 不存在“动画显示吃掉，但文件仍在”。
- 不存在“文件永久删除却未警告”。
- 正常退出后没有残留托盘图标或后台进程。

2. 记录本项目中遇到的失败模式与经过验证的解决方法。
3. 将角色专有数据抽成配置和素材槽位。
4. 创建一个可复用的个人 Codex Skill。
5. Skill 应能接收一张同类型角色图片，执行素材条件检查，并指导或完成从单图到同功能桌宠的端到端流程。
6. Skill 必须包含安全测试要求，尤其禁止对用户真实文件进行删除测试。

该 Skill 只在本项目最终验收后制作，避免把未经验证的临时方案固化成模板。

## 16. 完成定义

项目完成必须同时满足：

- 本规格中首版范围全部实现。
- 自动化测试与 Windows 集成测试通过。
- 用户要求的修改全部完成。
- 用户对视觉、音效和交互进行最终验收并明确通过。
- 交付免安装 ZIP 和源码。
- 最终验收后完成工作流记录与可复用 Skill。

在用户书面批准本规格前，不进入实施计划或代码阶段。
